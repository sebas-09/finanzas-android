## Verificación ejecutada

- Build completo: `test :app:assembleDebug :app:assembleDebugAndroidTest :core:database:assembleDebugAndroidTest lint` → BUILD SUCCESSFUL.
- Cuatro pruebas JVM, cero fallos: centavos exactos, rechazo de redondeo/overflow, ventanas de captura e invariantes de registros confirmados.
- `:core:database:connectedDebugAndroidTest :app:connectedDebugAndroidTest` → BUILD SUCCESSFUL en Android 10/API 29 y Android 16/API 36, AOSP x86_64 con aceleración WHPX.
- Por cada API: dos pruebas de BD aprobadas y una de navegación aprobada. La prueba de procesos figura omitida en la suite general por diseño y se ejecutó separadamente mediante el script: escritura → force-stop → lectura, ambas fases aprobadas en cada API.
- Android 16 ejecutó el recorrido de navegación con modo oscuro y font_scale=2.0. Android 10 usó configuración clara y escala normal. Revisión visual de capturas; no se declara TalkBack probado en dispositivo físico.
- La prueba de cifrado verifica cabecera distinta de SQLite, rechazo de apertura con SQLite sin clave y reapertura posterior con SQLCipher. Otra prueba comprueba que la ausencia de secreto no restablece ni elimina la BD existente.
- Manifest fusionado debug y release: sin INTERNET, SMS/contactos/cámara/ubicación, permisos generales de archivos ni listener de captura; allowBackup=false y reglas de extracción configuradas.
- APK debug instalado y abierto en ambos emuladores. Firma de desarrollo verificada con apksigner. No se generó un APK release firmado para distribución final.

Resultados legibles por máquina, reportes JUnit y extractos de consola en [evidence](evidence/results.json). Capturas: [Android 10](screenshots/welcome-api29.png) y [Android 16, oscuro y texto grande](screenshots/welcome-api36-dark-large.png).

## Observaciones del entorno

El SDK, emuladores y caché de Gradle se prepararon dentro de `.tooling/`, fuera del código versionado. No se modificaron JAVA_HOME ni el SDK global de Windows. rtk no estaba disponible; se utilizaron comandos nativos para diagnóstico y ejecución.

Tras mover el icono, la caché incremental local omitía ese recurso aunque el archivo era válido. Se corrigió regenerando `:app:processDebugResources :app:processReleaseResources --rerun-tasks --no-build-cache`; después el build normal y lint pasaron. Si Windows bloquea classes.jar al limpiar, detener primero el daemon del proyecto con `gradlew --stop`.

## Límite de esta fase y siguiente paso

No se han solicitado permisos de notificaciones ni habilitado fuentes; no se han probado paquetes o formatos bancarios reales. El APK permite explorar la base de interfaz y comprobar almacenamiento, sin registrar movimientos. No se afirma que CA-01–CA-12 estén completos: la matriz indica su fase de aceptación.

F1 comienza con el esquema financiero, onboarding persistente, selección de fuentes reales, ventanas de consentimiento y NotificationListenerService. La captura bancaria exigirá validación en un teléfono físico; las muestras PeiGo siguen pendientes para F6.
