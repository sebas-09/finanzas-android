# Verificación F5

F5 añade exportación consciente mediante el selector de documentos, borrado mediante la limpieza de datos propia de Android y firma release configurable por el propietario. La entrega local es debug; el usuario decidió proporcionar la clave de producción más adelante. Ver [guía de datos e instalación](../user/F5-DATOS-Y-ENTREGA.md) y [decisión técnica](../decisions/008-exportacion-borrado-f5.md).

## Comprobaciones

Las 51 pruebas JVM incluyen las regresiones anteriores y cuatro pruebas CSV: comas/comillas/saltos Unicode, fórmulas precedidas por espacios o controles, centavos hasta Long.MAX_VALUE, documento vacío y fallo del escritor. El formato usa UTF-8, comas y registros CRLF; no convierte dinero mediante coma flotante.

Las pruebas instrumentadas nuevas verifican exportación con snapshot consistente, exclusión de pendientes/sintéticos/borrados/fusiones, operaciones propias y categoría efectiva de devoluciones después de reclasificar su compra. Comprueban cancelación, error de proveedor y los controles de confirmación sin ejecutar un borrado durante la suite general. El listener real recibe una ráfaga acotada de ocho hijos agrupados y descarta un resumen financiero de grupo. No se extrapola esa ráfaga a una garantía de captura ilimitada.

StorageFailureTest comprueba rollback ante fallo de posting, límite de páginas SQLCipher y clave envolvente inaccesible sin reset automático. El límite provoca rechazo de crecimiento de la BD; no llena físicamente el volumen del emulador. EncryptedDatabaseTest comprueba además que una copia sin clave es ilegible y que el original sigue abriendo.

El probe F5DeliveryProbe se omite intencionalmente en la suite general. Su ejecución explícita en AVDs dedicados prepara una instalación F4 con saldo, operación, regla, presupuesto, consentimiento, cola cifrada, archivos y claves de ensayo; actualiza a F5 conservándolos; después comprueba el borrado real desde la interfaz, claves renovadas, ausencia de metadatos anteriores y ventana de captura nueva que rechaza publicaciones antiguas. Solo se registran hashes de marcadores sintéticos. El probe no usa pm clear como sustituto del botón de la app.

El recorrido CSV abre el selector de documentos real, guarda el movimiento de ensayo y comprueba que el archivo externo permanece idéntico tras limpiar los datos de la app.

El resumen final comprobable se guarda en [results.json](evidence-f5/results.json); sus logs, firmas y pruebas acompañan ese archivo en [evidence-f5](evidence-f5/). Las revisiones visuales se conservan en [screenshots-f5](screenshots-f5/).

La auditoría de fuentes productivas revisa llamadas de logging, exclusiones de backup/transferencia y el árbol release de dependencias. El único dump técnico del listener contiene estados, causa técnica y contadores; no cuerpos, títulos, importes ni alias financieros. El manifest fusionado debug/release se verifica con una lista de permisos y componentes públicos protegidos. Esto es evidencia estática local y no un volcado de mensajes de bancos reales.

La actualización API 29 pasó primero por un build F5 anterior y después por el binario final; API 36 actualiza directamente desde F4. El reinicio solicitado con ADB dejó su transporte sin respuesta: se recuperó únicamente el QEMU del AVD dedicado y se inició el mismo disco sin borrarlo. El probe confirmó claves y datos conservados tras ese arranque en frío. El reinicio mediante ADB sin incidencias sigue pendiente; el [log del entorno](evidence-f5/environment-api29-reboot.log) conserva el detalle.

El [fallo inicial del probe](evidence-f5/probe-fixture-failure-api29.log) ocurrió después de comprobar eliminación de BD/claves/datos: faltaba provider en el fixture nuevo de reactivación. Se corrigió el fixture, se repitió la suite final y el probe aprobó. También se ajustó el conductor UI para esperar al selector y reconocer el texto real de captura desactivada. El APK principal mantuvo su hash durante esas correcciones del ensayo.

El primer probe sobre F4 en API 36 terminó por ANR de inicio del proceso antes de ejecutar su test, mientras Android todavía procesaba BOOT_COMPLETED. El reintento tras estabilizar el arranque aprobó y luego se ejecutaron las suites finales. Se conserva el [registro](evidence-f5/environment-api36-initial-probe.log), sin extrapolar estas pruebas a rendimiento de un teléfono físico.

La revisión visual incluyó diálogos claros en API 29, oscuros con texto al 200 % en vertical y texto al 100 % en horizontal en API 36. Se comprobó desplazamiento hasta el reconocimiento, cancelación y botones visibles. Durante esa revisión apareció un [ANR de System UI](evidence-f5/environment-api36-system-ui-anr.png); se cerró únicamente el componente del sistema y se continuó. No sustituye la validación hablada de TalkBack ni pruebas de rendimiento físico.

## Reproducir

Con JDK 17 y Android SDK/Build Tools 36:

~~~powershell
.\gradlew.bat test :app:assembleDebug :app:assembleDebugAndroidTest :core:database:assembleDebugAndroidTest :app:assembleRelease lint --no-daemon --no-parallel --max-workers=1
python tooling/verify-manifest.py debug
python tooling/verify-manifest.py release
.\gradlew.bat :app:dependencies --configuration releaseRuntimeClasspath --console=plain > dependencies-release.log
python tooling/audit-privacy.py --dependency-report dependencies-release.log --output privacy-audit.json
.\gradlew.bat :core:database:connectedDebugAndroidTest :app:connectedDebugAndroidTest --no-daemon --no-parallel --max-workers=1
.\tooling/test-process-restart.ps1 -Adb adb -Serial emulator-5558 -SkipBuild
~~~

Para el ensayo destructivo usar un AVD llamado finanzas-f5-api29 en puerto 5558 o finanzas-f5-api36 en puerto 5560, sin datos personales. Conservar el artefacto F4 y firmar los APK de pruebas y aplicación con el mismo certificado debug. Ejecutar secuencialmente el helper con fases seed, upgrade, export y reset:

~~~powershell
python tooling/test-f5-delivery.py --adb RUTA_ADB --serial emulator-5558 --phase seed --allow-test-data-clear
python tooling/test-f5-delivery.py --adb RUTA_ADB --serial emulator-5558 --phase upgrade --allow-test-data-clear
python tooling/test-f5-delivery.py --adb RUTA_ADB --serial emulator-5558 --phase export --allow-test-data-clear
python tooling/test-f5-delivery.py --adb RUTA_ADB --serial emulator-5558 --phase reset --allow-test-data-clear
~~~

El helper rechaza teléfonos físicos, otros puertos y AVDs sin el nombre dedicado. Preparar un AVD nuevo para seed, sin cuentas ni versiones posteriores instaladas; el helper no fuerza downgrade ni desinstalación. No se reejecuta seed sobre una instalación ya preparada. Las pruebas del listener conceden/revocan acceso a avisos sintéticos. Restaurar permisos y ajustes visuales al finalizar.

## Aceptación pendiente

TalkBack hablado, bancos reales y restricciones OEM requieren teléfono físico. El release optimizado sin firma solo demuestra compilación/R8; la firma final y su instalación limpia/actualización esperan el keystore del propietario. La transición desde debug a un certificado distinto requiere decidir expresamente qué hacer con los datos; no se fuerza desinstalación ni se promete restauración desde CSV.

La matriz CA-01–CA-12 distingue regresiones sintéticas de aceptación bancaria física. No se declara terminado el MVP ni verificado un formato bancario real sin esas evidencias. La CI queda preparada para compilar también release sin firma y auditar privacidad; no se ha ejecutado remotamente desde esta entrega local.
