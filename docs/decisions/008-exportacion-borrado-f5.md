# 008 — Exportación y borrado F5

El CSV representa movimientos confirmados y vigentes de una instantánea transaccional. Incluye operaciones propias con su tipo y sentido, para que no se interpreten como consumo. Las devoluciones resuelven la categoría actual de la compra original, en concordancia con Insights. Excluye pendientes, sintéticos, borrados y filas absorbidas por conciliación. No es un respaldo: no contiene claves, reglas, observaciones ni historial para restaurar la app.

La exportación solicita un destino mediante ACTION_CREATE_DOCUMENT, sin permisos generales de almacenamiento ni temporales propios en claro. Se escribe UTF-8, separador coma, todas las celdas entrecomilladas, comillas duplicadas y registros CRLF. Los importes usan decimal exacto de dos lugares y fechas con desplazamiento de Guayaquil. Los textos que empiezan con =, +, - o @ tras espacios/controles se prefijan con apóstrofo para reducir interpretación de fórmulas. No se promete protección si otra herramienta elimina ese prefijo al reprocesar el archivo. Los errores del proveedor se comunican sin mostrar URI ni excepciones y pueden dejar un documento parcial en el destino elegido.

El borrado exige un diálogo y reconocimiento explícito. CaptureManager bloquea callbacks y acciones pendientes inmediatamente, pausa la sesión si el almacenamiento está disponible y descarta la cola RAM. Después se cancelan trabajos y avisos propios. ActivityManager.clearApplicationUserData solicita al sistema limpiar los datos de este paquete: Android termina el proceso y elimina almacenamiento privado, archivos auxiliares de SQLite, preferencias, cachés, tareas y claves Keystore del UID. Se evita reabrir singletons Room/Hilt sobre archivos eliminados. No se concede CLEAR_APP_USER_DATA ni se utiliza pm clear como implementación. No se promete sobrescritura forense del almacenamiento flash.

La operación debe funcionar también si no se puede abrir la BD. Si Android rechaza la petición o falla la preparación, se muestra un error y se mantiene la captura bloqueada hasta reabrir la app; no se declara éxito. Al reabrir tras un borrado efectivo se presenta el consentimiento inicial y todas las fuentes están deshabilitadas. Las plantillas de categorías/reglas pueden recrearse; ninguna regla personalizada debe reaparecer. El siguiente inicio de captura fija una ventana nueva y no importa historial.

Los documentos guardados con SAF pertenecen al destino elegido por el usuario y quedan fuera del borrado de datos de la app. Un proveedor SAF de nube puede sincronizar el archivo por su propia cuenta; la app sigue sin INTERNET.

La firma release consume cuatro variables FINANZAS_RELEASE_* y falla ante configuración parcial. Sin ellas se puede compilar un release optimizado sin firma para revisar R8/manifest, pero no se entrega como instalable. El usuario decidió proporcionar su keystore más adelante; no se genera ni almacena una clave de producción en el repositorio. Cambiar de certificado impide actualizar una instalación existente salvo que exista una línea de firma compatible.
